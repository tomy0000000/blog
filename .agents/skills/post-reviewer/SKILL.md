# Post Reviewer

審閱 `content/posts/<slug>/index.zh-tw.md` 的文章草稿。定位是編輯，不是代筆：指出問題、附上具體改法，但不直接改稿，除非使用者明確要求套用。

這個部落格是個人散文，重視真誠的敘事與口語感之間的平衡。目標不是把文章改成教科書，而是拿掉稀釋力道的贅詞、補上讀者需要的脈絡，讓故事自己說話。

## 流程

1. 完整讀一遍文章，先掌握主旨、想傳達的情緒、目標讀者，再開始逐項檢查。不要邊讀邊挑毛病，第一遍的閱讀體驗本身就是重要的資料。
2. 跑 `python3 .claude/skills/post-reviewer/scripts/analyze.py <文章路徑>` 取得機械式檢查報告：贅詞統計（含行號）、「我」字比例與全站基準、中英文空格、半形標點、破折號與分號、footnote 對應、front matter 缺漏、長段落。
3. 對照 script 輸出再讀一次文章，找有沒有清單外的贅詞（同類的口語緩衝詞、濾詞）。有的話，把它們加進 `analyze.py` 的 `STOPWORDS` 與本文件的基準清單，然後重跑 script，以更新後的輸出為準。只加跨文章通用的詞，單篇語境才成立的直接在報告裡指出即可。
4. 依下列面向逐項檢查。機械式項目以 script 輸出為準，人工只做判斷（哪些該改、怎麼改），不要重複掃描。
5. 依「報告格式」輸出，問題按影響大小排序，小問題合併陳述。

## 檢查面向

### 1. 贅詞與口語濾詞

基準清單（可依文章語境動態增減）：

> 我、覺得、其實、然後、後來、所以、的部分、就算、也、即便、應該、可能、還有、差不多、大部分、老實說、或許

這些詞在口語裡是自然的緩衝，寫下來卻會稀釋句子的力道，或透露不必要的不確定。script 已列出每個詞的次數與行號，逐一檢視每個出現處：能刪就刪，不能刪就換更精準的詞。不是零容忍，關鍵是「這個詞有沒有在工作」。例如轉折處的「所以」若承擔邏輯就留著，純粹口頭禪就刪。統計是子字串比對，像「也許」會被算進「也」，判斷時留意。

「我」字特別處理：個人散文不可能不用，但連續句子都以「我」開頭、或比例明顯高於 script 給的全站平均時，改寫句構讓主詞退到後面。

### 2. 故事性

抽象的主張要有具體的場景、例子或數字撐著。找出「只有形容詞、沒有畫面」的段落，建議補上一個真實片段，或指出文中已有的素材可以搬過來用。Show, don't tell。

### 3. 起承轉合

- 起：第一段有沒有鉤子，讓人想讀第二段。
- 承：鋪陳是否推進，還是原地打轉。
- 轉：有沒有一個視角翻轉或張力點，全文最該用力的地方。
- 合：結尾是否收束並呼應開頭，留下餘韻，而不是突然斷掉或淪為口號。

### 4. Context、Purpose、Foreshadow

逐段檢查三件事：

- Context：讀者讀到這裡時，需要的背景都給了嗎？專有名詞、人名、內部梗第一次出現就要解釋（footnote 是這個部落格慣用的手法）。
- Purpose：這段對主旨有貢獻嗎？刪掉會不會更好？
- Foreshadow：後面的重點有沒有提前埋線？結尾的情緒是否在前文就開始累積？

### 5. 讀者視角

假設一個不認識作者、沒有相關背景的讀者從搜尋結果點進來：他能看懂嗎？會在哪一段迷路或關掉頁面？時效性的指涉（「今年年初」「上個月」）幾年後回看是否仍可理解。

### 6. 節奏與重複

- 句長要有變化，連續長句讓人喘不過氣，連續短句顯得急促。
- 找出重複的句式（例如連續的「⋯⋯的是」「因為⋯⋯所以⋯⋯」）與短距離內重複的用詞，建議換法。
- 段落長度是否失衡，一段超過五六行考慮拆分。

### 7. 標點與格式

中英文空格、半形標點、footnote 對應由 script 檢出，照輸出確認即可。需要判斷的是破折號與分號：script 只給次數與位置，逐一看是否可用逗號、句號或括號改寫，少量刻意使用可以保留。

### 8. Front matter

缺漏由 script 檢出（description、categories、tags、feature、draft flag）。人工補充的判斷：`description` 該怎麼寫才適合分享預覽與搜尋結果、`categories` 與 `tags` 的選擇是否貼合內容。`draft: true` 只提醒，不代刪。

## 報告格式

```markdown
## 總評
（兩三句：這篇文章最強的地方、最值得處理的一件事）

## 主要建議
（按影響排序，每項引用原文，說明問題，給出具體改法）

1. **[面向] 一句話描述**
   > 原文引用
   問題說明。
   建議：改寫範例或做法。

## 次要建議
（合併陳述的小問題：贅詞統計與位置、標點、front matter 缺漏）

## 不用改的地方
（一兩句：哪些看似「問題」其實是文章的特色，明確說不建議動）
```

「不用改的地方」這段很重要：審稿的目的是精修而不是消毒，明確標出保留的判斷可以避免下一輪修改把文章的個性磨掉。
